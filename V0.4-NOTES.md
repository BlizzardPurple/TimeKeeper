# TimeKeeper v0.4 — Planning Notes

## Issues from v0.3 Testing

### 1. Widget — live stopwatch using Chronometer

**Problem:** Widget doesn't reflect real-time state. Shows stale data between refreshes.

**User's idea (correct):** Once the widget knows the check-in time, it should run a local timer — no need for repeated syncs.

**Why it seemed hard (it's not):** Android widgets are static snapshots — no running threads. But Android provides `Chronometer`, a system-level component that counts up from a base time automatically. No syncing, no battery drain, no refresh needed.

**Solution — `Chronometer` RemoteView:**
- Use Android's built-in `Chronometer` widget component (a `TextView` that auto-ticks, managed by the system)
- On check-in: set `chronometer.base = SystemClock.elapsedRealtime() - (now - checkInTime)`, call `chronometer.start()` → it ticks automatically
- On check-out: replace with static `TextView` showing today's total (frozen)
- Implementation: drop from pure Glance to `RemoteViews` for the timer row (use `AndroidRemoteViews` interop in Glance, or switch to a traditional `AppWidgetProvider`)
- Still keep: status dot, weekly total, days count, check-in/out toggle button
- Widget syncs on check-in/out events + 15-min periodic. Between syncs, Chronometer handles the live counting.

### 2. Checkout notification radius too large (100m)

**Problem:** The 100m exit geofence triggers "Leaving office?" too easily — brief steps outside, nearby shop, etc.

**Fix:** Add a **5-minute dwell delay** on exit. Only fire the checkout notification if the user has been outside 100m for 5+ continuous minutes. Re-entering within 5 min cancels the pending notification. Simple, no extra radius config needed.

### 3. History resets when week ends

**Problem:** Past week history disappears after weekly reset.

**Root cause:** Either `WeeklyResetWorker` is deleting archived data, or History screen queries the wrong table. Need to debug the actual data flow.

**Fix:** Ensure archival correctly moves data to `weekly_summaries` + `archived_time_sessions` tables and History screen reads from `WeeklySummaryDao.getAllSummaries()`.

### 4. Off days (absences) persist into next week

**Problem:** "WFH/Leave Days This Week" carries over. Should auto-reset to 0 on Sunday 12pm.

**Fix:**
- Verify `WeeklyResetWorker` reliably resets absences
- Add safety check on app launch: if current time is past last reset boundary and absences > 0, reset them
- Belt-and-suspenders: worker handles scheduled reset, app launch handles edge case

### 5. History screen needs more detail

**Problem:** History view doesn't show enough information per day/session.

**Required details per archived week:**
- Date and day name (e.g. "Mon, Oct 27")
- Per-day: check-in time, check-out time, session duration, daily total
- Multiple sessions per day shown individually (not just aggregated)
- Days attended count, total hours, target met/missed
- Off days applied that week (e.g. "1 holiday — target reduced to 2d/16h")
- Week summary: total time completed, days completed, target status

### 6. Weather-based smart departure suggestions

**Idea:** Integrate weather data to give the user smart "leave by" suggestions.

**Concept:**
- Fetch hourly weather forecast for the office location (calibrated GPS coords)
- While checked in, monitor upcoming weather (next 2-3 hours)
- If rain/storm is predicted, calculate: "You need X more minutes to hit your target. Rain starts at 6:15 PM. Leave by 5:55 PM to beat the rain."
- Notification: "🌧️ Rain expected at 6:15 PM. You'll hit your 24h target by 5:50 PM — leave by then to stay dry!"
- Also useful for: extreme heat alerts, storm warnings
- Could show a small weather indicator on the dashboard (current + next few hours)

**Implementation approach:**
- Use a free weather API: OpenWeatherMap (free tier: 1000 calls/day) or Open-Meteo (completely free, no API key)
- Open-Meteo is preferred — no API key, no rate limits, good hourly forecasts
- API: `https://api.open-meteo.com/v1/forecast?latitude={lat}&longitude={lng}&hourly=precipitation_probability,precipitation,weather_code&timezone=Asia/Kolkata`
- Check weather every 30 min while checked in (via WorkManager periodic task or alongside NotificationCheckWorker)
- Combine weather + remaining hours logic:
  1. How much time does user still need today/this week?
  2. When does bad weather start?
  3. Calculate: "finish target by [time], leave by [time - commute buffer]"
- Commute buffer: configurable in Settings (default 15 min)
- Notification types:
  - "Rain in 2 hours — you'll finish your target in 45 min, plenty of time"
  - "Heavy rain at 5:30 PM — leave by 5:15 to avoid it. You'll have 23h 40m this week (20 min short)"
  - "All clear today — no rain expected"

**Dashboard integration:**
- Small weather card on dashboard (optional, below weekly progress):
  - Current: ☀️ 32°C
  - Next: 🌧️ Rain at 6:15 PM
  - Suggestion: "Leave by 5:55 PM"
- Only shows when relevant (rain/storm predicted). Hidden on clear days to keep dashboard clean.

**Settings:**
- Enable/disable weather suggestions (default: on)
- Commute buffer time (default: 15 min)
- Weather data source: Open-Meteo (no config needed)
